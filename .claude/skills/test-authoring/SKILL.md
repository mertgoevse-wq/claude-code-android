# test-authoring

## The one question

**Would this test fail if the production change were reverted?**

If not, it is not a test. It is a line of code that will survive a regression
and report success, which is worse than no test at all. That case is a blocker,
reviewed as seriously as a wrong implementation.

## What must be covered

| Layer | Target | What |
|---|---|---|
| `shared/domain` | >= 90 % line | Rules, policies, parsers, state machines, cost math, budget, anti-loop, permission policy |
| `shared/data` | >= 80 % | Repositories against in-memory Room, Ktor against a mock engine, bootstrap against a fake filesystem |
| Contract | must not break silently | `AgentEvent` / `OutboundMessage` against recorded fixtures from real engine output |
| UI | every screen, every state | content, loading, empty, error, dark, light, 360 dp, font scale 1.3 |
| Screenshot | baselines committed | Paparazzi, per screen per theme, diffs looked at |
| E2E | five journeys | On an emulator, every merge |
| Security | all hard blocks | Including "attempt to delete is refused" |

Boundaries, the empty case, and the error path are **not** optional. A screen
without an empty state is an unfinished screen.

## Test data safety

No real API key, no real token, no real private repository, no real user
content. Ever. Not in a fixture, not in a screenshot, not in an example.

- Fixtures are generated by `tools/`, never hand-typed from something real
- Hosts use `.invalid`; keys are visibly fake and carry a `FIXTURE-` prefix
- Anything resembling a credential in a fixture is a finding
- `bash scripts/check-no-secrets.sh` covers the working tree

A leaked fixture is a real leak, and it is in git history forever.

## Patterns

```kotlin
@Test
fun `verdict differs from the agent's claim when verification is red`() = runTest {
    // A judge that always agrees with the agent is decoration, not a judge.
    val verdict = judge(task = "make it work", verification = VerificationResult.Failed("1 test failed"))
    assertFalse(verdict.succeeded)
}
```

- Turbine for `Flow`: `flow.test { assertEquals(expected, awaitItem()) }`
- `kotlin.test` and MockK; Robolectric only where the platform is genuinely needed
- In-memory Room and a Ktor `MockEngine`; no network in a unit test, ever
- Property-based cases for parsers, cost math, and the retry counter
- One behaviour per test. A test asserting five things fails for five reasons

## Running

```bash
./gradlew :shared:domain:test --tests '*TheThing*'   # narrow, while iterating
./gradlew check                                      # the real gate
./gradlew :shared:domain:koverVerify                 # the threshold
```

## Banned

Lowering a threshold, `@Ignore`, `@Disabled`, `runAllTests = false`, deleting a
failing test, or `--no-verify`. All of these are hard block 5 and all are review
blockers. A red gate is fixed with a test or reported as a blocker. It is never
made to disappear.

## Flaky tests

A flaky test is a broken test. Do not add a retry. Find the cause: a real clock,
a real network, a real filesystem, a shared mutable fixture, or an order
dependency. `runTest` gives you a virtual clock; use it.
