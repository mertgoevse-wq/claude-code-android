# Fixtures and test data

Every byte a test reads that is not written by the test itself comes from here. The rule that shapes this document: **fixtures are committed, small, and obviously fake**.

## Where things live

| Path | Contents | Committed |
|---|---|---|
| `fixtures/projects/` | Sample repositories used by integration and E2E tests | Yes |
| `fixtures/contracts/<version>/` | Recorded Claude Code event streams | Yes |
| `fixtures/events/` | Hand-written event JSON for parser tests | Yes |
| `fixtures/skills/` | Minimal skill repositories | Yes |
| `fixtures/api/` | Recorded HTTP request/response pairs per provider | Yes |
| `fixtures/github/` | Recorded GitHub API responses and paginated sets | Yes |
| `fixtures/terminal/` | Recorded terminal byte streams, including ANSI sequences | Yes |
| `fixtures/certificates/` | Throwaway TLS certs and a test CA for runner tests | Yes |
| `src/test/resources/` | Small inline test data only | Yes |
| `build/test-data/` | Generated by tests at run time | No |

## The sample projects

Four, each chosen to exercise a different verification path. None of them is a real-world repository, and none carries a real licence obligation beyond the ones we wrote.

### `gradle-buggy` — the primary fixture

A minimal Gradle project (Kotlin JVM library, three source files, three tests) with **one test that genuinely fails**. This is the fixture behind E2E Journey 1 and the retry journey.

- Real `settings.gradle.kts`, real `build.gradle.kts`, a real wrapper.
- The failing test asserts on a function that returns the wrong value.
- It must build in under 40 s on a mid-range CI machine, or the E2E suite becomes unreliable.
- A sibling variant `gradle-buggy-unfixable` has a test that cannot pass without a network dependency that is unreachable in CI.

### `npm-cli` — a different ecosystem

A three-file Node project with a `test` script and a deliberately failing assertion, so the verification judge is tested against npm output as well as Gradle output.

### `rust-lib` — a compiled language

A tiny Cargo library, one failing unit test. Covers the `cargo test` output path and a compiled build step.

### `plain-scripts`

A `Makefile`-driven directory with a shell test script and no framework at all. This is the fixture that proves exit-code-only verification works, and the one that most often breaks the judge.

## The rules for a new fixture

1. **It must build offline.** No fixture may reach the network at any point. Anything that needs a dependency is either vendored into the fixture or avoided.
2. **It must be small.** Under 1 MB per project, under 200 files. A fixture that takes 30 s to build makes the E2E suite optional, and an optional suite is a missing suite.
3. **It must be deterministic.** Fixed timestamps, no random names, no clock-dependent assertions.
4. **It must be obviously fake.** No real names, no real keys, no real hostnames, no real issue numbers. `example.com` and `test-key-placeholder` only.
5. **It must have a README** saying what it exercises and which test uses it. A fixture nobody can identify becomes dead weight nobody dares delete.

## Event fixtures

`fixtures/events/` is organised by the concern it tests:

| File | Purpose |
|---|---|
| `minimal-success.stream.jsonl` | The shortest well-formed run: init, one message, result |
| `with-tools.stream.jsonl` | Multiple tool calls, results, mixed success and error |
| `with-subagents.stream.jsonl` | `parent_tool_use_id` nesting, interleaved lanes |
| `with-retries.stream.jsonl` | `api_retry` events, out-of-order counters |
| `partial-messages.stream.jsonl` | `stream_event` deltas for token streaming |
| `unicode.stream.jsonl` | Emoji, CJK, RTL text, combining marks, an emoji ZWJ sequence |
| `malformed-*.stream.jsonl` | One file per malformed case from `unit-tests.md` §1.2 |
| `interrupted.stream.jsonl` | Ends without a `result` — the `INTERRUPTED` path |
| `cancelled.stream.jsonl` | Exit 143 — the cancelled path |
| `huge-line.stream.jsonl` | One 5 MB line, to test the length guard |

A generator script, `fixtures/events/generate.py`, produces the malformed and fuzz seeds. Generated files are committed so a test never depends on running the generator.

## HTTP fixtures

Recorded request/response pairs, sanitised the same way as contract recordings:

```
fixtures/api/anthropic/streaming-success.http
fixtures/api/anthropic/rate-limited.http
fixtures/api/anthropic/overloaded-529.http
fixtures/api/openai/chat-stream-success.http
fixtures/api/openai/tool-call.stream.http
fixtures/api/openai/responses-api.stream.http
fixtures/api/custom/generic-compatible.http
```

Each file contains the request we sent, the response headers, and the response body with any real key or account id replaced by `<redacted>`. The sanitiser is a script in the repo and a review checklist item, because a fixture that leaks a key gets committed by someone who trusted the tool.

The tests replay these through OkHttp's `MockEngine`, so the real HTTP stack, the real SSE parser, and the real retry interceptor are all exercised.

## Terminal fixtures

Raw byte sequences with escape codes, committed as files so the terminal parser is tested against real output rather than against what we believe escape codes look like:

| File | Contains |
|---|---|
| `basic.txt` | Plain text with newlines |
| `colors-16.txt` | All 16 ANSI colours and the bright variants |
| `styles.txt` | Bold, dim, italic, underline, inverse, strikethrough |
| `cursor-moves.txt` | `CUU`, `CUD`, `CUF`, `CUB`, `CUP`, `CHA` |
| `erase.txt` | `EL`, `ED` in all modes |
| `alt-screen.txt` | Enter and leave the alternate screen buffer, a real Claude Code behaviour |
| `osc-title.txt` | `OSC 0` and `OSC 2` title setting |
| `bracket-paste.txt` | `ESC[200~` … `ESC[201~` |
| `bell.txt` | `BEL` |
| `long-line.txt` | A 50 000-character line with no newline |
| `utf8-box.txt` | Box-drawing characters and emoji in a grid |

## Keys and credentials in fixtures

There are none, by policy rather than by accident. See `test-data-safety.md` for the rules and the enforcement. The short version: every key-shaped string in `fixtures/` is a literal placeholder such as `sk-ant-test-0000000000000000`, and a CI check fails the build if any fixture matches a real key pattern with a plausible length.

## Adding a fixture

```
fixtures/<kind>/<name>/
  README.md          what it exercises, which tests use it, what to keep in sync
  ...                 the data
  meta.json           optional: expected values tests can assert against
```

1. Write the README first. If you cannot describe what it exercises in two sentences, you do not yet know what it is for.
2. Run it through the sanitiser.
3. Reference it from the test; a fixture no test uses is deleted at review.
4. Add it to the index below.
